# Triple review — governed self-learning v2

Date: 2026-08-31

Scope: complete fork upgrade from post-hoc golden-path capture to an auditable,
owner-governed learning lifecycle.

## Review 1 — architecture, evidence, and scope: PASS

Checked:

- original fork structure and upstream golden-path mechanism;
- upstream requests for provenance/replay receipts and stronger secret checks;
- primary research on external reflection/experience, skill libraries, curriculum,
  iterative refinement, memory tiers, provenance, and AI risk management;
- TeamON One ownership and runtime boundaries;
- failure modes of saving every reflection as an active rule.

Findings resolved:

- separated checkpoint, tentative note, governed memory, skill, canonical knowledge,
  and skip paths;
- added exact positive/negative applicability boundaries;
- added candidate states and immutable version transitions;
- kept Learning as a governed transition, not a new runtime/store/memory plane;
- bounded autonomous practice to authorized tasks, sandbox, budget, judge, and stop
  conditions;
- explicitly excluded model-weight-training claims and hidden reasoning storage.

Remaining architectural limitation: retrieval and evaluation quality still bound the
achievable improvement; no external skill system can guarantee monotonic improvement.

## Review 2 — implementation and evaluation: PASS

Local validation executed against the final working tree:

```text
python -m compileall -q skills/self-learning/scripts
python -m unittest discover -s tests -v
python skills/self-learning/scripts/learning_cycle.py validate-skill skills/self-learning --harvested
JSON parse of manifests and all JSON assets
empty-workspace init + audit smoke test
```

Result: 30 unit tests passed.

Covered behaviors:

- ledger creation, hash chaining, and tamper detection;
- explicit configuration updates and unknown-key rejection;
- secret rejection and evidence requirements;
- source-event validation;
- strict candidate-ID/path traversal rejection;
- deterministic artifact hashes and post-review drift blocking;
- symlink rejection;
- three distinct independent review assertions;
- failed/non-independent/stale review blocking;
- exact host approval signature and candidate binding;
- explicit weakening for local-manual mode only;
- probation threshold and conservative reliability;
- default owner-approval hold;
- opt-in low-risk project activation;
- protected-domain activation block;
- failure-burst archive;
- revision invalidation of reviews, approval, and trials;
- recurring-gap ranking and duplicate coverage exclusion;
- next-action queue, reports, audits, and harvested-skill validation.

Evaluation caveat: unit tests validate the state machine and safety invariants. Real
agent-quality gains still require domain replay suites and owner/objective judgments.

## Review 3 — safety, governance, and compatibility: PASS

Checked:

- secret leakage patterns;
- prompt-injection persistence boundary;
- identity/mission/authority/permission/policy protection;
- exact artifact substitution and symlink/path attacks;
- self-review/self-approval;
- unbounded background behavior;
- production/network/financial authority growth;
- rollback and stale-skill behavior;
- Windows/Linux and Python 3.10+ compatibility;
- upstream MIT attribution.

Findings resolved:

- approval request is bound to candidate ID, version, subject hash, and artifact
  hash;
- default approval is externally signed; local-manual is explicitly marked unsafe
  for shared agent authority;
- candidate edits force a new version and reset all gates;
- protected domains never auto-activate;
- repeated failures and weak reliability archive candidates;
- external content remains evidence, not standing authority;
- state hash chain is documented as tamper-evident, not tamper-proof;
- HMAC symmetry and host key-isolation limitation are documented;
- reviewer identifiers are not misrepresented as proof of real independence.

## Independence disclosure

The three passes above are separate review lenses performed in one implementation
workstream, plus deterministic tests. They are not three independent human reviewers.
The repository itself therefore requires host-enforced distinct reviewer
identity/session/context before a learned candidate becomes active in a protected
production deployment.

## Decision

PASS for pull request and CI review. Do not bypass repository/owner approval when
integrating this mechanism into TeamON One composition.
